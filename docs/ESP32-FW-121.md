# ESP32 (плата у инвертора): прошивки FW 121 «rs232_ew10» и FW 122 «rs232_fixes»

Документ про **C++-прошивку** платы ESP32 из проекта
`/volume1/WD4/AI/esp32invertormonitornovyi` (Arduino / PlatformIO, `env esp32dev`).
Это не MicroPython-фирмварь из `firmware/esp32/*.py` этого репозитория — та живёт
отдельно и на этой плате даёт нестабильный Wi-Fi (см. §7).

Готовые образы лежат в репозитории (`firmware/esp32/builds/`):

| Версия | Файл | sha256 | Размер |
|---|---|---|---|
| 121 | `121_esp32dev_rs232_ew10.bin` | `79206389…efb493` | 1 085 120 |
| **122 (текущая)** | `122_esp32dev_rs232_fixes.bin` | `5c2d7cba…cf333d9` | 1 086 192 |

## 1a. Что исправлено в FW 122

1. **Приборы (полукруги) всегда были в полный круг.** Причина: `/data` отдавал
   `max_w = 2` — паспортная мощность однажды распарсилась из мусорного кадра (шум на
   свободном RX), а масштаб гаутов считается как `мощность / max_w * 100` → 13 950 % → дуга
   закрашивалась целиком. Теперь паспортные значения проверяются на здравый смысл
   (`100…50000`), в `/data` мусор не отдаётся (`max_w ≥ 100`, иначе 1000), в JS такой же
   предохранитель. Проверено: `max_w = 11000`, дуги показывают реальный процент.
2. **«Нет связи» теперь видно на экране.** Баннер в дашборде:
   «Нет связи с инвертором N с — показаны последние полученные данные» (и «Данных ещё
   не было», если кадров не было ни разу). При отсутствии связи приборы обнуляются.
3. **История больше не засоряется.** `maybeRecordHistory()` пишет точку только если
   инвертор отвечал в пределах `INVERTER_OFFLINE_MS`; раньше писались плоские повторы
   последнего кадра.
4. **Подтяжка RX** (`INPUT_PULLUP`) при источнике UART: свободный вход ловил шум
   (в диагностике было `uart_rx = 69` при отсутствии провода).
5. `source_mode` в *Miscellaneous* показывает фактический источник:
   `UART платы (RS232 direct)` или `EW10 / RS232-TCP 192.168.31.110:9999`.

Проверено на плате (`/data`): при источнике EW10 — `inv_online: Да`, `max_w: 11000`,
`ow: 2098 Вт`, `hist_count` растёт; при переключении на UART без провода — `inv_online: Нет`,
значения обнуляются, появляется баннер, история не растёт.

## 1. Зачем

Домашний инвертор занят донглом **EW10** (RS232 → TCP, `192.168.31.110:9999`), а офисный — на
Raspberry Pi по USB. Плата ESP32 стоит рядом с инвертором и умеет две вещи:

1. **Быть источником данных**: сама опрашивать инвертор и отдавать цифры в свою панель и MQTT.
2. **Быть RS232-мостом**: отдавать UART инвертора в TCP, чтобы сервер `solar-monitor`
   опрашивал инвертор по сети (транспорт «Виртуальный RS232»).

В FW 121 у обоих режимов появился **выбор источника**: провод (UART платы) или **EW10 по сети**.
Это и просили: «принимать от EW10 тоже».

## 2. Что на странице `/rs232` (только админ)

| Блок | Поля | Смысл |
|---|---|---|
| **Источник данных инвертора** | `UART платы` \| `EW10 / RS232-TCP`, host, port | откуда брать кадры PI30. Для EW10 по умолчанию `192.168.31.110:9999` |
| **Мост наружу (TCP → RS232)** | галочка «Включить мост», TCP-порт (по умолчанию `9999`) | отдаёт поток инвертора TCP-клиенту (серверу solar-monitor) |

Пока TCP-клиент подключён, **локальный опрос платы приостанавливается** — на линии 2400 бод
два мастера несовместимы. После отключения опрос возвращается сам.

Статус на странице: включён ли мост, слушающий порт, IP клиента, байты в обе стороны
(+ «последний байт N с назад»), счётчики подключений/обрывов, состояние связи с EW10.

## 3. Как подключается

**Вариант A — плата читает EW10** (без провода; порт инвертора занят донглом):
`/rs232` → источник `EW10 / RS232-TCP` → host `192.168.31.110`, port `9999` → «Сохранить».
Данные идут в панель платы и в её MQTT.

**Вариант B — сервер читает плату** (провод к инвертору, GPIO25 RX / GPIO26 TX, 2400 8N1):
на `/rs232` включить мост, в solar-monitor — **Настройки → Подключение** →
«Виртуальный RS232 (TCP)» → host = IP платы, port `9999` → «Проверить связь».

**Вариант C — сервер читает EW10 напрямую**: тот же транспорт, host `192.168.31.110`, port `9999`.

## 4. Проверено на живой линии (2026-11-20)

```
EW10 192.168.31.110:9999 → QPIGS: 229.8/229.9 В, 49.9 Гц, нагрузка 298 ВА / 236 Вт,
                                  АКБ 52.90 В, SOC 98 %
                            QPIRI: 230 В / 50 Гц, 11 кВт, 48 В банк, bulk/float 57.6 В
                            QMOD : B (battery mode)
```

- Донгл **держит несколько TCP-клиентов**: два одновременных клиента получили валидный `QPIGS`,
  при этом коллектор на VDS продолжал опрос без ошибок (`ok: true`, age 2.3 с).
  Значит читать из EW10 можно параллельно; запись уставок — по-прежнему только одним мастером.
- Плата после заливки поднимается, панель отвечает (`401` без пароля — это норма).

## 5. Как заливать

OTA (без шнура): панель платы → `/ota` → выбрать `121_esp32dev_rs232_ew10.bin`.

USB, только приложение (NVS/SPIFFS сохраняются — Wi-Fi, MQTT, `totals.bin`):

```bash
esptool.py --chip esp32 --port /dev/cu.usbserial-110 --baud 460800 \
  write_flash -z --flash_mode dio --flash_freq 40m --flash_size 4MB \
  0x10000 firmware/esp32/builds/121_esp32dev_rs232_ew10.bin
```

Полная прошивка с нуля (если стёрли flash), раскладка как у FW 119:

```
0x1000  bootloader.bin     (из .pio/build/esp32dev/)
0x8000  partitions.bin     (nvs 0x9000, otadata 0xe000, app0 0x10000, app1 0x150000, spiffs 0x290000)
0x10000 firmware.bin
```

## 7. Почему не MicroPython-фирмварь из этого репозитория

Плата (ESP32-D0WD-V3, 4 МБ, CH340) изначально работала на **C++**-прошивке этого проекта.
MicroPython-вариант (`firmware/esp32/*.py`) на ней дал нестабильный Wi-Fi (`Wifi Internal Error`,
`ECONNABORTED`, пустой `scan`) даже при отдельном питании. Для MicroPython-варианта в репозитории
сделаны отдельные правки (адрес заливки `0x1000` для классического ESP32, `wdt_s`, сторож задач,
отправка ответов кусками, пауза при молчащем инверторе) — они пригодятся на другом модуле,
но на этой плате рабочая прошивка именно C++ (FW 121).

## 8. Реализация (для правок)

- `app/app_invsrc.inc` — абстракция транспорта: `invAvailable`, `invRead`, `invReadUntilCR`,
  `invWriteBuf`, `invDrain`, `invFlush`; выбор источника в `invsrc`, конфиг `/invs.txt` в SPIFFS.
- `app/app_rs232.inc` — мост: `rs232BridgeLoop()` в `loop()`, страница `/rs232`, конфиг `/rs232.txt`.
- `sendInverterCommand()` (в `app/app_services.inc`) собирает кадр PI30 (команда + CRC + CR) и
  отдаёт его `invWriteBuf()` — так кадр уходит и в UART, и в EW10.
- Чтение кадра ограничено 600 мс и 100 мс тишины: блокирующее ожидание на 2400 бод иначе
  морозит веб-сервер и MQTT (это уже проходили на MicroPython-варианте).
