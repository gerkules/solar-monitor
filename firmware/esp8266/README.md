# Прошивка Wemos D1 (ESP8266): панель инвертора + мост TCP ⇄ RS232

Плата у инвертора отдаёт линию PI30 в TCP, чтобы **Orange Pi / сервер `solar-monitor`
опрашивал инвертор по сети** транспортом «Виртуальный RS232 (TCP)», а без сервера
показывала данные сама — схемой потоков и графиком в браузере.

База — уже проверенный на железе проект владельца:
`/volume1/WD4/AI/esp32invertormonitornovyi/wemos_usb_firmware/wemos8266_lite.cpp`
(FW 118). Добавлено:

* TCP-сервер (по умолчанию `9999`), прозрачный мост `TCP ⇄ UART` — **включается
  по желанию** (вкладка «Мост» или `bridge on` в CLI), по умолчанию выключен:
  плата работает как обычный локальный монитор;
* пауза локального опроса, только пока трансляция включена **и** клиент подключён
  (на линии 2400 бод два мастера несовместимы);
* новая панель (FW 124): SVG-схема потоков — солнце/панели → инвертор → дом, сеть, АКБ,
  анимированные провода по направлению мощности, метрики и график мощностей за час;
* CLI по USB-serial для настройки без телефона/AP.

## Железо

| Плата | ESP8266EX, 4 МБ flash (Wemos D1 / D1 mini) |
|---|---|
| UART инвертора | **SoftwareSerial: RX = D5 (GPIO14), TX = D6 (GPIO12)**, 2400 8N1 |
| Уровни | MAX3232 (инвертор — настоящий RS232, ±12 В), питание модуля 3V3 |
| Serial (USB) | 115200, для логов, CLI и прошивки |

```
Wemos D5 (GPIO14) ◄── MAX3232 R1OUT      MAX3232 T1IN  ◄── Wemos D6 (GPIO12)
Wemos GND         ──── MAX3232 GND        MAX3232 R1IN  ──► инвертор RS232 TX
                                           MAX3232 T1OUT ─► инвертор RS232 RX
```

Линия инвертора: **2400 бод, 8N1**, без flow control. Порт у инвертора один — донгл
EW10 и Wemos одновременно на один разъём не вешаются.

`builds/126_wemos_d1_esp8266_rs232_ui.bin`


Прошивка по USB (адрес `0x0`, NVS/настройки сохраняются):

```bash
esptool.py --port /dev/cu.usbserial-XXXX --baud 230400 write_flash -z 0x0 \
  builds/124_wemos_d1_esp8266_rs232_ui.bin
```

или из проекта:

```bash
cd ~/solar-monitor/firmware/esp8266
~/.platformio/penv/bin/pio run -t upload --upload-port /dev/cu.usbserial-XXXX
```

Если плата была в цикле сброса на `rf cal sector: ...` — служебная область flash
побита, помогает `esptool.py erase_flash` перед заливкой (проверено на этой плате).

## Веб-интерфейс

`http://<ip>/`, Basic-авторизация: `admin` / пароль админа (по умолчанию `admin`).

| Вкладка | Что внутри |
|---|---|
| **Схема** | SVG power-flow: PV с солнцем и панелями, сеть, инвертор, дом с панелями на крыше, АКБ с уровнем заряда. Провода «текут» по направлению мощности (разряд АКБ — в обратную сторону), 4 живые метрики, график load/PV/batt/grid за последний час |
| **Настройки** | уставки инвертора (`POP`/`PCP`/`PBT`/`MCHGC`/`MUCHGC`), Wi-Fi, пароль админа, OTA |
| **Мост** | галочка «разрешить трансляцию» + кнопка «Сохранить мост» (без перезагрузки страницы), состояние TCP-клиента, байты в обе стороны, порт и baud |
| **Диагностика** | прошивка, uptime, свободная RAM, RSSI, кадры OK/ошибки, последний кадр |

HTML/CSS/JS (~16 КБ) — `ui_html.h`, лежит в **PROGMEM** и отдаётся через `send_P()`,
в куче не держится (свободно ~40 КБ RAM). Данные: `GET /data`, история:
`GET /history` → `{"pts":[[load,pv,batt,grid],...]}` (360 точек по 10 с), запись
уставок: `POST /set`.

## Первая настройка

Вариант A — через AP (пока нет Wi-Fi):

1. подключиться к `InverterMonitor` / `12345678`;
2. открыть `http://192.168.4.1/`, логин `admin` / `admin`;
3. **Настройки**: SSID, пароль Wi-Fi, пароль админа → «Сохранить и перезагрузить»;
4. вкладка **Мост**: TCP-порт и baud → «Сохранить мост».

Вариант B — по USB-serial (115200):

```
show
ssid <имя сети>
pass <пароль>
port 9999
baud 2400
bridge on          # включить трансляцию (без него плата только мониторит)
reboot
```

## Подключение к Orange Pi (solar-monitor)

В UI `solar-monitor` → **Настройки → Подключение → Виртуальный RS232 (TCP)**:
host = IP Wemos (лучше закрепить DHCP-резерв на роутере), port = `9999` →
«Проверить связь». Или в `.env`:

```
TRANSPORT=tcp
TCP_HOST=<ip-wemos>
TCP_PORT=9999
```

Порядок: на Wemos включить трансляцию (галочка на вкладке «Мост» или `bridge on`), затем
на сервере «Проверить связь». Пока сервер опрашивает инвертор, панель показывает последние
полученные данные, но сама линию не трогает. После отключения клиента локальный опрос
возвращается через ~1 с. Выключить трансляцию — снять галочку / `bridge off`: порт
закрывается, плата снова работает как самостоятельный монитор.

## Диагностика

| Симптом | Что смотреть |
|---|---|
| панель «Нет связи», `/data` → `online: Нет` | провода D5/D6, MAX3232, 2400 8N1, занят ли порт донглом |
| TCP-клиент подключается, но ответов нет | `br_tcp2uart` растёт, `br_uart2tcp` = 0 → RX от инвертора не приходит |
| плата в цикле сброса, boot-лог `rf cal sector` | `esptool erase_flash` и залить заново |
| нет AP при первом включении | кнопка RESET, затем USB-serial 115200 |

`GET /data` (после Basic-авторизации) отдаёт также мост и служебное:
`br_active`, `br_client`, `br_tcp2uart`, `br_uart2tcp`, `br_sessions`, `br_age`,
`br_enabled`, `br_port`, `baud`, `ssid`, `ip`, `rssi`, `up`, `heap`.
