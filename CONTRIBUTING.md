# Как участвовать

Спасибо за интерес! Проект небольшой и практический: главное — не сломать работу с реальным железом.

## Прежде чем начать

1. Прочитайте [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) — там структура кода и рецепты
   («добавить метрику», «добавить язык», «добавить драйвер BMS», «добавить транспорт»).
2. Проверьте, что тесты зелёные:

   ```bash
   cd collector && python3 -m unittest discover -s tests
   node --check solar_monitor/web/static/app.js
   node --check solar_monitor/web/static/i18n.js
   ```

## Правила, которые мы соблюдаем

* **Никаких «успехов» без подтверждения.** Запись уставки считается успешной только после
  чтения `QPIRI`; недостоверные данные лучше не публиковать, чем публиковать выдуманные.
* **Строгая валидация кадров.** На общем UART может прийти чужой кадр с валидным CRC — все новые
  парсеры должны проверять и содержимое (`QMOD` = одна буква, `QPIWS` = 40 бит, `QPIGS2` = `P ≈ U·I`).
* **Тест на каждый баг.** Сначала падающий тест с реальным кадром, потом фикс.
* **Никаких секретов в репозитории.** Пароли, токены, серийники и адреса живут в `.env` и
  `/data/*.json`. В примерах — только заглушки (`192.168.1.60`, `TEST000000000001`).
* **UI без сборки.** `app.js`/`i18n.js`/`styles.css` — обычные файлы, без npm и транспиляции.
  Новые строки интерфейса — сразу в три словаря (`ru`/`en`/`el`).
* **Совместимость.** Поддерживаем Python 3.9+ (проверяется локально) и 3.12 (в контейнере).

## Pull request

* Одна логическая правка = один PR, с описанием «что проверено и на чём».
* Если меняется поведение — обновите соответствующий файл в `docs/` и `docs/CHANGELOG.md`.
* Приложите вывод `python -m unittest discover -s tests` (или скриншот UI, если правка визуальная).

## Баг-репорт

Откройте issue по шаблону `.github/ISSUE_TEMPLATE/bug_report.md` — там нужные поля
(модель инвертора, прошивка, транспорт, лог). Без этого диагностировать почти невозможно.

## Что особенно приветствуется

* проверка драйверов BMS на реальных батареях (JBD, Daly, Pylontech, Seplos, JK);
* новые протоколы уставок для нестандартных прошивок (`SETTINGS_JSON`);
* переводы (сейчас RU/EN/EL);
* Grafana-дашборды для других наборов метрик.
